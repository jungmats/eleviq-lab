1 The problem

Most of what a website could sell to a visiting agent — a report, a dataset, one API call — usually just sits behind a wall marked "free" or "not available." Not because it has no value, but because there's no ordinary way for an autonomous agent to actually complete a purchase: no card number to type, no checkout page to click through, no human standing by at the moment of the request.

HTTP has had a status code for exactly this since 1997 — 402 Payment Required — almost entirely unused until now. This demo turns a real resource behind it into something an agent can actually pay for, on its own, with no human involved once it starts.

The question here isn't who owes money for this. It's how an agent, acting entirely on its own, completes a real payment for something a server has priced.

The mechanism is x402, an open protocol built directly on 402: the server states a price, the agent signs a payment authorization, and a real settlement happens on a public ledger — no card network, no bank, no account for either side to sign up for.

Real money never changes hands here: this runs on Base Sepolia, a free practice copy of a real blockchain, using testnet USDC — worthless-by-design digital dollars made for exactly this kind of demo. Everything else about the flow — the signature, the on-chain settlement, the balance change — is genuine, not simulated.

    4 Test it from your own tools

    The console above is a convenience. The gateway is a plain public HTTP API.

    A — See the price, nothing to install

    curl -i https://eleviq-lab-gateway.gateway-worker.workers.dev/api/charge/report

    Returns 402 with the exact x402 payment requirements — price, asset contract, network, and where payment goes.

    B — Complete the payment yourself

    Completing it needs an EIP-712 signature over an EIP-3009 transferWithAuthorization message — real wallet cryptography, not a one-line curl flag. The published demo wallet (reference/charge-agent.json) holds a real private key on Base Sepolia; this page's own script (assets/charge.js) is the reference implementation for building and sending that signature, using viem. The resulting base64 payload goes in an X-PAYMENT header on a repeat of the same request.
